# Android release optimisation (SDK 54)

## Configuration

- `expo-build-properties` 1.0.10 enables `android.enableMinifyInReleaseBuilds` and `android.enableShrinkResourcesInReleaseBuilds` for release builds.
- `plugins/with-android-release-optimization.js` selects `proguard-android-optimize.txt` instead of SDK 54's default `proguard-android.txt`, which disables optimisation. It preserves app/library compatibility keep rules and fails clearly if the generated template changes.
- No SDK, Android minimum OS, target API, iOS configuration or application ID changes are needed.
- R8 is part of the existing Android Gradle Plugin 8.11.0 toolchain. No separate obfuscator is added.
- Production builds retain the R8 mapping/diagnostic directory as EAS build artifacts. Download and retain these per build for native crash deobfuscation. Upload a matching mapping file if Play does not extract one from the AAB.

## Build and verify

```sh
# Release APK, using production environment and credentials, with no store submission.
npx eas-cli build --platform android --profile release-validation

# Store AAB; also does not submit automatically.
npx eas-cli build --platform android --profile production
```

The validation profile inherits production settings, switches output to APK/internal distribution, and disables build-number increments for the test artifact. Production still uses remote auto-incremented build numbers. Both keep app version 1.0.1.

Do not assess R8 using Expo Go, a development client, or JavaScript-only export. Test the release APK or a Play internal-test installation of the AAB.

For an AAB, inspect `BUNDLE-METADATA/com.android.tools/r8.json` for the metadata Play uses. Inspect `BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map` and the mapping artifacts for `mapping.txt`, `configuration.txt`, `usage.txt` and `seeds.txt` where produced. Confirm R8 has run, inspect optimisation/obfuscation/shrinking percentages, and check for broad `-keep`, `-dontobfuscate`, `-dontshrink` or `-dontoptimize` restrictions before changing compatibility rules.

Release test checklist: cold launch/relaunch, login and stored sessions, product/vendor browsing, refresh, cart, location permissions/search, Paystack checkout/callback using a safe test transaction, image picking/display, notification permissions/opening, and deep links. Native reflection/JNI compatibility failures may appear only in optimised release builds; add narrow keep rules only when the release test/build evidence requires them.

Upload the AAB to Play **internal testing** and confirm Play's reported optimisation scores before a production rollout. This task does not submit or publish to Play. A successful build or local R8 metric does not guarantee that Play has cleared its alert for an older release, or that a separate memory-vitals finding is resolved.

## R8 compatibility finding

The first R8 AAB build exposed five missing optional Stripe Issuing push-provisioning types. Stripe declares that SDK as `compileOnly`; SMM uses Paystack and does not call its card-provisioning feature. The exact five `-dontwarn` rules generated by R8 are added through `extraProguardRules`. There is no blanket `-dontwarn`, no package-wide suppression, and optimisation stays enabled. If card provisioning is introduced later, include and test the real Stripe Issuing dependency instead of relying on these optional-type rules.

## Native option decoding failure — 9 November 2026

The Android device report (`smm-location-v1`, app 1.0.1/build 17, Android 35) confirms fine permission and enabled GPS/network providers. `watchPositionImplAsync`, `getCurrentPositionAsync`, and `getLastKnownPositionAsync` each reject their options with `ERR_UNEXPECTED`, a cast failure to `LocationOptions`/`LocationLastKnownOptions`, and a nested `NullPointerException`. This happens before a provider fix is requested; further permission changes or longer GPS timeouts cannot repair that conversion.

The installed SDK 54 `RecordTypeConverter` reads `memberProperties`, runtime `@Field` property annotations, and `property.javaField` through Kotlin reflection. Existing Expo consumer rules keep record classes/members, but the app rules did not explicitly retain `kotlin.Metadata`. R8 full-mode metadata handling is therefore the leading release-only cause. The app now preserves Kotlin metadata, reflection attributes, and Expo's record conversion package while retaining minification, shrinking and optimisation for the rest of the application. This also protects native option records used by clipboard operations. No SDK upgrade or additional location permission is involved.

Reference: https://developer.android.com/topic/performance/app-optimization/full-mode#kotlin-specific-metadata

Validate using a new `release-validation` APK with R8 enabled. Confirm current location works after cold start, permission grant and app resume; try approximate permission too. If it fails, use View / copy location report and Share location report. Inspect the new mapping/configuration artifacts to confirm the keep rules are present. Native changes require a rebuilt binary; an OTA JavaScript update cannot install ProGuard rules. Automated configuration checks do not establish successful GPS operation on a physical device.
